# forgeHQ Tier Applicability Matrix

**Current repo truth:** forgeHQ is a contract/bootstrap repo with a Phase 1 scaffold, not a live shaping service.

| Tier | Applicability | Current rationale |
| --- | --- | --- |
| T0 | Applicable now | Documentation assembly, context loading, pytest discovery, and repo test execution are real current surfaces |
| T1 | Applicable now | Governance, documentation, worker, schema, orchestration, and QA-foundation contracts are implemented |
| T2 | Not applicable until UI exists | No browser, desktop, or operator UI exists in this repo |
| T3 | Not applicable until API exists | No HTTP or RPC API exists in this repo |
| T4 | Not applicable until live runtime and multi-module flows exist | The repo has no live service runtime or adapter-backed integrations |
| T5 | Not applicable until live runtime and multi-module flows exist | No executable end-to-end user journey exists yet |
| T6 | Limited applicability now | Only documentation/test-tool responsiveness can be measured; no UI/API/load surface exists |
| T7 | Not applicable until packaging/release targets exist | The repo has no packaged runtime, image, or release artifact |
| T8 | Not applicable until UI exists | Accessibility testing begins when forgeHQ owns a UI surface |
